# kuuuu33.github.io

制作物をまとめるトップページ。https://kuuuu33.github.io/

`index.html` 1枚と、画像を入れた `assets/` だけで動いています。ビルド作業はありません。
書体だけ Google Fonts（Zen Old Mincho / Zen Kaku Gothic New）を読み込んでいます。

## 構成

```
index.html          本体。HTML・CSS・JSが全部入り
assets/
  kurage-fight.jpg    作品01のスクリーンショット
  planetarium.jpg     作品02のスクリーンショット
  ogp.jpg             SNSシェア時のカード画像（1200×630）
  favicon-32.png / icon-512.png / apple-touch-icon.png
LICENSE
```

## 作品を追加する手順

1. 作品そのものを別リポジトリで公開する（例: リポジトリ名 `xxxx` → `https://kuuuu33.github.io/xxxx/`）
2. スクリーンショットを撮り、横1200pxくらいのjpgにして `assets/` に入れる
3. `index.html` の `</main>` の手前にテンプレートがコメントで置いてあるので、`<article>` ごとコピーして貼り付ける
4. 変えるのは6か所 — `href`（2か所）／画像と `alt`／番号／カテゴリ／タイトルと説明／タグ3つ
5. GitHubに反映する（下記「更新のしかた」参照）。1〜2分で公開ページに出ます

**ヒーローの `2 PROJECTS` は自動で数えるので、手で直す必要はありません。**

配色は1つおきに変えると単調になりません。`<article class="work reveal">` がシアン、
`<article class="work work--gold reveal">` が金です。

## 更新のしかた

このMacにはGitHubの認証情報が入っていないため、ターミナルからの `git push` は認証で止まります。
いまは **GitHubのWeb画面からアップロード** する運用です（リポジトリを開く → Add file → Upload files → ドラッグ＆ドロップ → Commit changes）。

ターミナルから push できるようにしたい場合は、アクセストークン（Settings → Developer settings → Personal access tokens、スコープ `repo`）を発行したうえで、
`git config --global credential.helper osxkeychain` を実行してから push すると、以降は入力不要になります。

# ⚠️ 新しい作品を作るときのルール：保存キーに接頭辞をつける

**新作でセーブデータを扱うなら、ここを必ず読んでください。**

## なぜ必要か

ブラウザの保存領域（localStorage / IndexedDB）が分かれる単位は、**パスではなくオリジン**です。

```
https://kuuuu33.github.io   ← この単位で「引き出し」は1つだけ
  ├─ /                        まとめサイト
  ├─ /planetarium/
  └─ /kurage-fight/           ← 全部この同じ引き出しを共有している
```

つまり各作品は別サイトではなく、**保存領域を共有しています**。
別々の作品が同じキー名を使うと、**お互いのセーブデータを上書きして壊し合います**。

## ルール

保存キーは必ず **作品ごとの接頭辞** から始めること。

```js
✕  localStorage.setItem('best', score)        // 他の作品と衝突する
◯  localStorage.setItem('punipuni-best', score)
```

IndexedDB のデータベース名も同様に `作品名-save` の形にすること。

### 現状（衝突なし）

| 作品 | 保存 |
|---|---|
| くらげファイト | localStorage 17キー、すべて `kurage-` 接頭辞。IndexedDB は `kurage-save` |
| プラネタリウム | 保存なし |
| まとめサイト | 保存なし |

## 既存作品を更新するときの注意

- **キーを増やすのは安全。名前や保存する中身の形を変えるのは危険** — 既存プレイヤーのデータが読めなくなります
- くらげファイトの `index.html` には `KEYS` という配列があり、**IndexedDBへのバックアップ対象はこのリストに載っているキーだけ**です。保存項目を追加したら、ここへの追記を忘れないこと

## プレイヤー側の事情で消えるケース

作り手の操作では消えませんが、以下では消えます。長く遊ぶ作品には引き継ぎ機能を用意しておくと安全です（くらげファイトの「💾 データ」画面が実装例）。

- ブラウザの「履歴とサイトデータを消去」／プライベートブラウズ
- **iOS Safari**：7日間そのサイトを訪れないと保存データが自動削除される（IndexedDBも同じ扱いなのでミラーも効かない）。「ホーム画面に追加」すれば対象外
- 別の端末・別のブラウザは、そもそも別データ

## 将来カスタムドメインを当てる場合

独自ドメインに移すとオリジンが変わるため、**過去のセーブデータは全て見えなくなります**。
移行するなら、事前にプレイヤーへ引き継ぎコードの取得を案内すること。
`kuuuu33.github.io` のまま運用する分には問題ありません。
